# Reproducible research: a practical collaboration protocol

**Mojtaba Roozegar — independent research and enterprise profile | 25 October 2026**

This open protocol is a useful starting point for proposed studies in agricultural economics, production systems, technology and enterprise decision-making. It is **not** a journal publication, peer-review certificate, proof of university affiliation or claim that a specific project has been approved.

## 1. Write the research question before collecting evidence

Specify the population or production system, intervention/exposure, comparison, outcome, geography and observation window. For example: “Across comparable production units, how does a specified irrigation scheduling rule affect water use per kilogram of marketable yield over one growing season, relative to the current practice?” A question must be falsifiable and answerable with available data.

## 2. Register an analysis plan

Before analysis, document:

| Item | Minimum evidence |
|---|---|
| Research question | Versioned question, scope and exclusions |
| Design | Experimental, observational, simulation or mixed-methods rationale |
| Sampling | Inclusion/exclusion rules, recruitment or field selection |
| Primary outcome | Unit, measurement instrument and collection frequency |
| Secondary outcomes | Defined separately from exploratory findings |
| Sample size | Justification or an explicit feasibility limitation |
| Missing data | Collection controls and predeclared handling rules |
| Confounding | Covariates and plausible alternative explanations |
| Analysis | Planned model, uncertainty intervals and sensitivity checks |
| Governance | Permissions, consent where applicable, data minimization and retention |
| Changes | Dated amendment log distinguishing planned from post-hoc analyses |

Do not label an unregistered analysis as “preregistered.” When formal preregistration is appropriate, use a recognized registry and keep its receipt.

## 3. Keep a chain of evidence

For every figure or table, record source ID, collection date, measurement unit, preprocessing version, analysis script/version, exclusions and reviewer notes. Do not mix measured values, model outputs and assumptions in one column without explicit labels.

Example file manifest:

```text
project_id: AGR-EXAMPLE-001
protocol_version: 1.0
dataset_status: not_collected
data_dictionary: pending
analysis_plan_status: draft
consent_or_legal_basis: not_yet_evaluated
independent_validation: not_performed
publication_status: none
```

This is a **blank example**, not a description of a completed study.

## 4. Separate scientific and commercial gates

A research output can be methodologically useful yet commercially unready. Maintain two distinct checklists:

- **Scientific validity:** traceable data, adequate design, uncertainty reporting, replication attempt, limitations and conflict-of-interest disclosure.
- **Commercial readiness:** actual buyer need, permitted use, delivery capability, quality acceptance criteria, lawful contracts, payment terms and after-sales responsibility.

Neither gate is satisfied by attractive visual presentation, generated text or automated scoring alone.

## 5. Publish results with calibrated claims

A useful public result distinguishes observed associations from causal effects, measured outcomes from estimates, and internal review from independent peer review. If no external journal has accepted the work, do not call it “peer-reviewed publication.” State null results, deviations and uncertainty without hiding them.

## 6. Start a legitimate collaboration

A collaborator can prepare a one-page concept with: research question, data ownership, intended outcome, available resources, methodological constraints, ethics/legal issues, desired contribution, budget status and contact permission. Sensitive personal, commercial or genetic data should not be attached to unsolicited messages.
