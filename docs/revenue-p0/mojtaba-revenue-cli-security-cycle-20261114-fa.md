# چرخه E — رفع موانع غیرضروری در مسیر استعلام، سفارش و درآمد ربات واحد

**تاریخ:** ۱۴ نوامبر ۲۰۲۶ / ۲۳ آبان ۱۴۰۵
**هویت یکتا:** `mojtaba.bot.ai`، بدون ایجاد ربات مستقل.
**شاخه پایه:** `audit/mojtaba-income-intake-safe-sync-20261114`، PR #2274 (Draft).
**شاخه اصلاح:** `audit/mojtaba-income-cli-safety-20261114`، فقط کد و آزمون، بدون تغییر تولید.
**محدوده اقتصادی:** ده مدل درآمدی فهرست‌شده در `scripts/mojtaba_revenue_portfolio.py`، دو خدمت فعلی دارای استعلام پیش‌نویس، بدون صدور فاکتور یا دریافت پول.

## نقص واقعی اثبات‌شده
در چرخه پیشین `revenue_dual_offer_qualifier.py` از خواندن امن JSON و گزارش خصوصی استفاده می‌کرد؛ ولی CLI اصلی ده‌مدلی `mojtaba_revenue_cli.py` دارای مسیر مستقل `json.loads`، `stat` سپس `read_bytes` و خروجی‌نویسی مستقل بود. JSON با رضایت دوگانه، عددهای `NaN/Infinity` و race condition فایل می‌توانست به شکل متفاوت یا ناامن تفسیر شود. **اکنون هر دو مسیر از `revenue_intake_io.py` استفاده می‌کنند.**

## تغییرات قابل‌استفاده
۱. ایجاد شاخه مستقل از HEAD بررسی‌شده PR #2274؛ جلوگیری از بازنویسی تغییرات هم‌زمان.
۲. تعمیم `read_strict_json` به `max_bytes` اختصاصی با type/value guard، حفظ سقف ۶۴KiB ابزار استعلام و ۳۲KiB ابزار کاتالوگ.
۳. `O_NOFOLLOW` و `O_NONBLOCK` هنگام باز کردن فایل؛ رد ورودی symlink و FIFO.
۴. کنترل `fstat` بعد از باز کردن فایل، رد فایل غیرعادی/بیش از حد مجاز.
۵. مقایسه اندازه و timestamps قبل/بعد از خواندن؛ fail-closed هنگام تغییر ورودی.
۶. رد JSON دارای کلید تکراری، از جمله `consent=false, consent=true`.
۷. رد `NaN`، `Infinity`، `-Infinity` و UTF-8 نامعتبر.
۸. افزودن محافظ قابل‌اندازه‌گیری `MAX_JSON_DEPTH=64` و `MAX_JSON_NODES=4096` برای داده‌های متادیتای کوچک؛ جلوگیری از پردازش درخت غیرمعمول.
۹. رسیدگی کنترل‌شده به `RecursionError` در parser با ValueError فاقد افشای داده مشتری.
۱۰. اتصال `mojtaba_revenue_cli.load_bounded_json` به همان parser با سقف ۳۲KiB و کنترل نوع dict.
۱۱. اتصال `output_private` CLI اصلی به writer مشترک؛ حفظ رد parent-symlink، حفاظت input/output و ساخت exclusive.
۱۲. فایل خروجی جدید فقط با مجوز 0600 و `fsync` ساخته می‌شود؛ هیچ فایلی بازنویسی نمی‌شود.
۱۳. ایجاد ۲۲ آزمون جدید subprocess برای CLI اصلی ده‌مدلی شامل PII، consent، JSON تکراری، FIFO، byte limit، راهنمایی و عدم ادعای پرداخت.
۱۴. افزودن ۶ آزمون IO (سقف خصوصی، deep JSON، تغییر فایل، RecursionError و موارد غیرمجاز) به ۱۵ آزمون قبلی.
۱۵. اجرای محلی ۲۱ آزمون IO؛ کشف **یک شکست واقعی**: JSON با عمق ۱۵۰۰ لزوماً در Python 3.13.5 خطا نمی‌دهد.
۱۶. پیاده‌سازی کنترل صریح عمق و تعداد گره؛ اجرای مجدد همان ۲۱ تست با **PASS کامل**.
۱۷. افزودن دو آزمون مرزی برای عمق دقیق ۶۴/۶۵ و تعداد گره‌های مجاز؛ اجرای محلی **۲۳/۲۳ PASS**.
۱۸. تطبیق SHA blob ماژول اجرایی از GitHub با `git hash-object` نسخه واقعاً اجراشده در محیط محلی.
۱۹. افزودن سقف محافظتی **فقط برای مقادیر ساختگی** `MAX_SYNTHETIC_COUNT=1_000_000_000` و `MAX_SOURCE_CHECKS=1_000_000`؛ هیچ محدودیتی بر مقدار پرداخت واقعی یا قیمت مورد توافق اعمال نمی‌کند.
۲۰. افزودن ۴ آزمون مرز محاسبات نمونه و جلوگیری از ادعای وصول پول از روی تعداد source checks.
۲۱. افزودن ۶ تست قرارداد منبع برای اثبات مسیر واحد reader/writer، یک ربات، نبود پرداخت/استقرار و عدم امکان عبور از محافظ مالی.
۲۲. اصلاح یک assertion قرارداد برای استفاده از imported canonical identity به جای وابستگی اشتباه به تکرار literal در فایل CLI.
۲۳. ثبت compile ماژول امن در Workflow ایزوله؛ آزمون‌ها با globهای موجود `test_revenue_*.py` و `test_mojtaba_revenue*.py` قابل کشف‌اند.
۲۴. بررسی GET-only وب برای `mojplaywin.com/services/`، `zomorodmelal.ir/services/` و `mojtaba.bot.ai`: ابزار عمومی پاسخ قابل اتکا نداد؛ **نه موفقیت و نه خرابی زنده** ادعا نمی‌شود.

## مراحل واقعی فروش که همچنان نیازمند گواه مستقل‌اند
- **SOURCE:** تطبیق HEAD، تست همه فایل‌ها در checkout دقیق PR و موفقیت CI.
- **LIVE:** مسیر صحیح دو صفحه خدمات و دامنه ربات، تست موبایل، فرم واقعی بدون داده مشتری.
- **LEGAL:** مجوز شخصی/کشوری قرارداد/مالیات/پشتیبانی، قیمت مصوب و سیاست لغو/بازپرداخت.
- **PAYMENT:** رسید مستقل پرداخت و تسویه، نه صرف وضعیت داخلی تراکنش.
- **DELIVERY:** فایل و خدمت نهایی با کنترل کیفیت، لینک امن، شواهد وصول مشتری و رسید تحویل.
- **FINANCE:** درآمد خالص **وصول‌شده** پس از بازپرداخت/کارمزد، با سند حسابداری واقعی.

قفل‌های حقوقی، مالی، امنیتی و محرمانگی «ایراد برنامه» نیستند و نباید بی‌مجوز برداشته شوند. در این چرخه قفل‌های ناشی از parsing ناهمگون و خواندن ناامن کد اصلاح شده است. هیچ فروش، استقرار، ادغام، ارسال ایمیل، معامله، پرداخت یا انتقالی انجام نشد؛ درآمد و درصد آمادگی تجاری کل **نامعلوم** باقی می‌ماند.
