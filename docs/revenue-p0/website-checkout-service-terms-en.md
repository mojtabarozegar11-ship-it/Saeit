# Website Sales & Checkout Repair — service quotation standard (EN)
Status: **draft terms, inquiry-only, not a binding public offer**. Brand: MojPlayWin. Execution belongs to the single canonical `mojtaba.bot.ai` workflow; no separate bot is created.

## What a buyer can request
- **Diagnosis (indicative USD 29–49):** one publicly reproducible sales-path/checkout problem; bounded HTTP, forms, error states and accessibility checks; anonymized evidence and one ranked root-cause assessment.
- **Bounded repair (indicative USD 79–149):** one approved defect with explicit files/routes, rollback plan, code changes, non-production tests, and a before/after verification report. Deployment is **excluded** until separately approved.
- These bands are experiments for demand assessment, **not a price confirmation**. A manual proposal must specify tax, currency, supported country, permitted method of collection, scope and total.

## Required inquiry / safety
Ask only for public URL, non-sensitive description, desired outcome, estimated affected steps and a preferred safe reply method. Do not request credentials, cards, cookies, session tokens, wallet seed phrases, customer information, or order history by email. Explicit consent is required before storing/contacting a prospect. Private access, if needed, must be arranged under a separately approved secure process.

## What is not promised
No guaranteed revenue, conversion-rate uplift, bank/processor approval, payment settlement, external API restoration, uptime, legal/regulatory compliance, or arbitrary number of fixes. No automated sale or delivery from an inquiry page.

## Acceptance and handover
1. Owner confirms lawful scope, eligibility, price, delivery date, revision window and written terms.
2. Only an approved collection route may issue an invoice; no manual assumption that TRX or card collection works.
3. A verified paid receipt must be independently checked. An unpaid inquiry is **not** revenue.
4. Deliver redacted reproduction steps, changed-file inventory, test outcomes and rollback instructions.
5. Customer acceptance and one defined correction window must be agreed case-by-case. Refund handling follows the specific approved written contract and applicable law; no blanket refund claims.
6. Keep customer secrets and deliverables off public GitHub.

**Commercial release gate:** legal/price/settlement/delivery owner approval AND end-to-end evidence. Otherwise no Buy Now CTA.
