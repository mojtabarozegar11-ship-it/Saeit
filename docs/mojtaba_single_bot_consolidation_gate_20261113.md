# دروازهٔ یک‌رباتی Mojtaba.bot.ai — ممیزی ۱۳ نوامبر ۲۰۲۶

## تصمیم معماری قطعی

هویت عمومی و عملیاتی مجاز فقط:

`mojtaba.bot.ai`

هر نام دیگر در یکی از دو مسیر قرار می‌گیرد:

1. ادغام کامل در `mojtaba.bot.ai` با رسید تحویل زنده و قابل‌تطبیق؛
2. حذف کامل فقط پس از احراز وابستگی‌ها، توقف زمان‌بندی‌ها، حفظ دادهٔ تاریخی و مجوز موردی مالک.

## وضعیت شواهد فعلی

| شاخص | وضعیت |
|---|---:|
| گروه‌های منبع ممیزی‌شده | ۹ |
| هویت‌های تعریف‌شده در کد، نه لزوماً ربات زنده | ۲۱ |
| نقش‌های PHP ثبت‌شده | ۱۱ |
| نقش‌های Django شناخته‌شده | ۱۰ |
| هویت یکتای هدف | `mojtaba.bot.ai` |
| موجودی کامل زندهٔ دو میزبان | اثبات‌نشده |
| تحویل زنده به ربات اصلی | اثبات‌نشده |
| خاموش‌سازی ربات‌های قدیمی | انجام‌نشده |
| حذف غیرقابل‌بازگشت | انجام‌نشده و مجازنشده |

## محدوده‌های هنوز شمارش‌نشده

- زمان‌بندی‌ها و آداپتورهای مستقل MojTrade
- workerها و زمان‌بندی‌های Moj Coin
- سرویس‌های systemd، cron و supervisor روی VPS
- پردازه‌های Passenger، PHP و cron در cPanel
- اتوماسیون‌های خارجی و اتصال‌های برنامه‌ای

## دروازهٔ ادغام

هر ادغام باید این شواهد را داشته باشد:

- شناسهٔ دقیق successor برابر `mojtaba.bot.ai`
- منبع و revision مستقرشده
- آزمون تحویل موفق
- رسید خروجی واقعی
- تعیین تکلیف taskهای در انتظار
- توقف زمان‌بندی قدیمی
- مسیر rollback
- عدم ایجاد اجرای موازی

## دروازهٔ حذف

حذف فقط زمانی مجاز است که:

- موجودی کامل میزبان‌ها انجام شده باشد؛
- هیچ task، scheduler، پرداخت یا انتشار وابسته باقی نمانده باشد؛
- داده‌های تاریخی حفظ شده باشند؛
- رسید تحویل successor ثبت شده باشد؛
- مجوز موردی مالک برای همان هویت صادر شده باشد.

## نتیجهٔ این چرخه

وضعیت فعلی: `READ_ONLY_BLOCKED`

هیچ رباتی در این چرخه حذف یا خاموش نشده است، چون موجودی کامل runtime و رسید تحویل زنده هنوز اثبات نشده است. این گزارش عمداً مانع ادعای «یک‌رباتی کامل» پیش از تکمیل شواهد می‌شود.
