# Mojtaba.bot.ai | Commercial offer portfolio and revenue-readiness gate
Date: 2026-11-14
Status: source-only Draft. No launch, deployment, customer contact, price approval, contract, live bot, payment or receipt is implied.

## Sales model
One canonical agent ID: `mojtaba.bot.ai`. This is a **routing identity** in repository source, not proof of a deployed bot or a license to deactivate legacy programs. All external offer links and future website changes require separate live verification and explicit owner approval. The site `mojtaba.bot.ai` is not represented as active.

The catalogue covers genuine, source-backed inquiry candidates for economics, water, feasibility, marketing, machinery, research, AI feasibility, cash-flow planning, café B2B supply, existing physical catalogue and farm-direct supply. The separate educational wheat tool is free acquisition only. Books, games and bot subscriptions remain **release blocked**. These are commercial **scopes and drafts**, not claims of deliverability or inventory.

## Strict cash-first sequence
1. Validate original source and legal right to offer each service.
2. Confirm the public inquiry page and a completed, consent-based lead in the authorized CRM; never submit dummy customer data.
3. Record minimum inputs, buyer problem, scope, decision-maker and genuine willingness to pay. Never create or collect customer data without lawful basis.
4. Confirm actual delivery capacity, personnel, licensing, quality and turnaround; distinguish consultation, analysis and regulated service.
5. Issue a price/quote only after explicit owner-approved terms, currency, tax position and contract; no invented numerical price.
6. Only activate a payment rail when merchant onboarding and server-side callback verification and settlement accounting are proven.
7. Deliver verifiable goods/services and record genuine receipts and customer acceptance. Revenue is **collected cash**, not traffic, clicks, proposals or token volume.
8. Record verified cost, refunds and taxes before computing contribution margin. No marketing spend before receipts and fresh owner approval.

## Sales lead prioritization
Priority 1: farm economics, water, feasibility, market study, café B2B, physical catalogue. Priority 2: machinery, research, AI advisory, cash flow, farm direct and free tool. Priority 3: digital books and game license pending delivery/legal proof. Priority 4: bot subscription pending runtime and billing. The bands are **decision heuristics**, not revenue forecasts.

## Independent live gates for each offer
`source_provenance` -> `public_presence` -> `lead_intake_receipt` -> `delivery_evidence` -> `owner_authorized_terms` -> `verified_payment_and_collected_cash`.
A green offline unit-test run only validates code and source metadata. It cannot turn any of the later gates green. For commercial sale, confirm the authentic order/receipt ID, payment settlement, customer privacy, refund policy and delivery. Review customer data exclusively in the authorized private system; never put it in public CI logs or GitHub issues.

## Measurement contract
- `offer_count`: count of source-backed draft scopes, not live products.
- `repository_source_verified_count`: files actually present at the tested Git commit.
- `inquiry_candidates_source_only`: offers with intake and deliverable **definitions**, not customers.
- `release_blocked_offers`: unlicensed/unverified digital and automated monetization channels.
- `purchases_verified_count`, `leads_verified_count`, `revenue_received_irr`: `null` when no authenticated private sales ledger was accessed; never convert unknown to 0.
- Zero counters for side effects refer only to this local inspection run, not company operations.

## Security, concurrency and operations
- Parser rejects duplicate JSON keys, duplicate offers, invalid scope, unsafe file paths, symlinks, invented prices, manual assertions of live deployment or owner approval, enabled payments and non-canonical agent identifiers.
- CLI emits aggregate non-PII operational metadata only. No email/phone/lead data, API tokens or payouts are stored.
- CI uses a hosted runner with contents:read, no secrets, no database and no network calls in the code; it never deploys or starts a bot.
- This branch is isolated from the concurrent legacy sitewide Draft PR #2266.
- Before any production change, audit actual cPanel/live file provenance and require specific owner approval. Keep existing site design unchanged.
