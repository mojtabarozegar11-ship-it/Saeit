# 40-family operational intake activation: private only

The installed one-pass workflow turns on executable **private work intake and routing** for all 40 known family profiles. This is not 40 public store listings, verified revenue, or 40 production manufacturing engines.

Each family gets an actively rechecked dispatch lane and blocker matrix from the real private commercial offer. Families with signed-source technical portfolio packages route to human/rights/product acceptance; families without proofs route to actual native builder engineering. The request queue processes up to three local requests per five-minute scheduler tick, creates individual SHA-bound private work tickets and receipts, rejects malformed or duplicate requests, and cannot accept payment, sign approvals or publish products.

Private path: /home/githubops/factory-runtime/private/autonomous-product-cycle/activation40/
- dashboard.json: exact 40 statuses, technical package counts, true sale blockers and local route probes.
- requests/ : local private on-VPS consumer writes a restricted permission *.json
- tasks/ and receipts/: persisted evidence for up to three requests per dispatcher run.
- processed/ and rejected/: exactly-once/idempotent state.

Schema for **real locally authorized** requests:
{"schema":"saeit.factory.private-family-request.v1","request_id":"humanowned_000001","family_id":"F24","intent":"custom_specification","title":"Custom original research handbook","specification":"Create a scoped original sample with independently verifiable evidence, rights permissions and a clearly documented review checklist."}

No source is trusted just because a JSON file exists; the directory must remain private, and an authenticated host-side connector must be wired before accepting live site customer or PII submissions. Synthetic 40-family probe requests are tested in a *separate* temporary root, not the live customer queue; the probe receipts are never claimed as customer orders or autonomous agent requests.

Site payment/revenue: **not enabled**. Real commercial activation requires individually verified contents, price, legal rights, refund and tax rules, signed buyer identity where applicable, payment settlement and downstream file delivery, and actual explicit product release approval. No live cPanel/publication, payment, billing, cron duplication or server exposure occurs.
