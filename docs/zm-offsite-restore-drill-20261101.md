# زمرد — آزمون مستقل بازیابی بکاپ رمزگذاری‌شده

این ابزار فقط برای فایل ZIP دانلودشدهٔ بکاپ **مدیریت خصوصی زمرد** است؛ تأیید آن به‌معنی سالم‌بودن همهٔ فایل‌های سایت یا بانک اصلی Passenger نیست.

## نمونهٔ موجود

- [اجرای موفق 41293910313](https://github.com/mojtabarozegar11-ship-it/Saeit/actions/runs/41293910313)
- نام آرتیفکت: zm-business-recovery-41293910313؛ نگهداری ۳۰روزه در GitHub، پس تاریخ انقضا را بررسی کنید.
- محتوای ZIP: business.sqlite3.f01enc و manifest.txt.

## اجرای واقعی و امن

۱. فایل ZIP را فقط روی رایانهٔ **آفلاین و قابل‌اعتماد** با دیسک رمزگذاری‌شده دانلود/منتقل کنید. کلید خصوصی رمزدار RSA و گذرواژه باید **فقط نزد مالک** باشند. آن‌ها را در مخزن، GitHub Actions Secrets، چت یا VPS کپی نکنید.

۲. روی همان سیستم، در یک دایرکتوری خصوصی با مجوز 0700 آزمون کنید:

    python3 -m pip install cryptography
    python3 scripts/zm_offsite_restore_drill.py \
      --artifact-zip /path/to/zm-business-recovery.zip \
      --private-key /secure/offline/recovery-private.pem \
      --passphrase-file /secure/offline/passphrase.txt \
      --scratch-root /secure/offline/empty-private-workdir

فایل‌های کلید و گذرواژه باید مجوز 0600 داشته باشند. ابزار ZIP را بدون استخراج ناامن بررسی می‌کند؛ سپس AES-GCM، SHA-256، یکپارچگی SQLite و جدول‌های ضروری را می‌سنجد. نسخهٔ رمزگشایی‌شده در پایان یا هنگام خطا از دایرکتوری موقت پاک می‌شود. گزارش فقط وضعیت را نشان می‌دهد، نه داده‌های کسب‌وکار. برای محو فیزیکی ردپا، دیسک محل اجرای آزمون باید رمزگذاری‌شده باشد.

۳. فقط خروجی OFFSITE_RESTORE_VERIFIED=true یک شاهد معتبر برای **همان آرتیفکت و همان پایگاه داده** است. تا زمان اثبات جداگانهٔ بازیابی فایل‌های سایت، همهٔ دیتابیس‌های اصلی و هویت دیتابیس Passenger، **حذف دسته‌جمعی بکاپ‌ها و انتشار دفتر مدیریت ممنوع** باقی می‌ماند.

اجرای CI مخزن از کلید و داده‌های **ساختگی** استفاده می‌کند و جای اجرای واقعی مالک را نمی‌گیرد.
