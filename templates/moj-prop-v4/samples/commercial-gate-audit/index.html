2. A sample failure trace

A visitor selects a product and receives a 200 page. On submit, the browser sends a human-readable option while Django requires a canonical value and returns HTTP 400. The site is visually reachable, but the lead never enters the CRM. This is a commercial launch blocker even though the page is attractive.

The corrective acceptance criterion is not a test-green badge alone: an authorized, consented real request must receive a durable ID, appear in the actual operator queue, preserve customer privacy, and be followed by a written scoped proposal and delivery. No payment should be requested before lawful handling is established.

3. Audit deliverable structure

A scoped engagement would provide a domain-by-domain route inventory; code and runtime evidence matrix; prioritized blocker register; security and privacy assessment; severity/owner/dependency for each repair; reproducible acceptance criteria; signed handoff; and an implementation plan constrained by the owner's financial approvals.

4. Stop conditions

Never mark a payment captured from a browser string, unverified transaction hash, token price display, mock webhook, or merely reachable URL. Never self-authorize production trading or circumvent consumer laws, account ownership or required provider permissions. When evidence is absent, state unknown and require a specific proof.

5. Completion definition

For a digital-download sale, completion means: authenticated customer entitlement → unique pending invoice → independently verified payment at the actual receiver → finality and replay controls → licensed content delivery → receipt and recoverability. Any missing stage keeps the commercial gate closed.
