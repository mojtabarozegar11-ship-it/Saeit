واقعیت فعلی:
- یک محصول واقعی آفلاین فارسی/انگلیسی ساخته شده؛ مسیر سفارش، تأیید سروری پرداخت، دانلود نسخه‌بندی‌شده، پشتیبانی و گزارش درآمد دارد.
- ۳۱ آزمون Python/Django و ۱۲ آزمون Node موفق بوده‌اند؛ مجموع ۴۳ آزمون. یک HTTP smoke موقت و محلی انجام شد، اما staging پایدار و QA واقعی مرورگر انجام نشده‌اند. هیچ پرداخت یا فروش واقعی انجام نشده است.
- Production تغییر نکرده. تنظیمات اصلی Django می‌خواند `SECRET_KEY`، نه `DJANGO_SECRET_KEY`. مقدار مؤثر Passenger را بدون چاپ مقدار در cPanel بررسی کن. Merchant و فروشنده/پشتیبانی/شرایط همچنان Pending Configuration و Pending Owner Approval هستند.
- اجرای Playwright محلی به‌علت نبود Chromium ممکن نشد؛ QA بصری و دستگاه واقعی را حتماً تکمیل کن و ادعای تأیید قبلی نکن.
- در درخت Production بیش از ۲۵هزار تغییر قبلی وجود دارد؛ `git add .`، reset/clean یا Commit آن‌ها ممنوع است. فقط تغییرات محدود همین ماژول را جدا نگه دار.

ترتیب کار:
۱) ابزار محاسبه و مسیر فروش را در محیط جدا روی مرورگر و عرض موبایل ۳۹۰ پیکسل تست کن: واحدها، خطاها، زبان، ذخیره، JSON، CSV، چاپ و بازشدن ZIP روی دستگاه واقعی. نقص‌ها را در همین شاخه رفع کن.
۲) امنیت پرداخت، CSRF، نشست یک‌ساعته سفارش، عدم دسترسی با callback تنها، idempotency، آرشیو فایل و عدم نشت اطلاعات را مستقل مرور کن. خروجی تست را ثبت کن.
۳) Merchant معتبر، هویت فروشنده، ایمیل پشتیبانی، قیمت ۱۴۹هزار تومان، شرایط و اصلاح کلید امن Django را با مالک نهایی کن. رمز و کلید را در گفتگو یا Git نخواه؛ از تنظیم امن سرور استفاده کن. پیش از تغییر امنیتی حساس تأیید انسانی بگیر.
۴) طبق ACTIVATION.md یک پیشنهاد انتشار مشخص با Commit و SHA بسته، diff محدود URL/template و روش rollback آماده کن. قبل از تغییر Production تأیید صریح مالک بگیر.
۵) تست درگاه واقعی را با محیط و داده جدا انجام بده. پس از اجازه انتشار و خرید آزمایشی، فقط یک پرداخت واقعی مورد توافق انجام شود؛ مبلغ سروری IRR، callback، دانلود و تیکت را بررسی کن. بازپرداخت/انتقال وجه فقط توسط مالک خارج از Agent انجام شود.
۶) پس از آماده‌شدن خرید، با اجازه مالک ۵ تا ۱۰ مشتری مرتبط را برای تست دعوت کن؛ هیچ Spam یا پیام بدون تأیید مخاطب/کانال ارسال نکن. محاسبه سفارش واقعی آن‌ها و willingness-to-pay را ثبت کن. درآمد را فقط از تأیید درگاه گزارش کن.
۷) KPIهای قیف و علت نخریدن را بررسی کن. اگر تقاضا تأیید نشد، پیشنهاد اصلاح یا توقف همین محصول بده؛ تعداد صفحات یا پست‌ها را موفقیت معرفی نکن.
۸) تغییرات خودت را تست، Commit و Push کن؛ گزارش دقیقِ آماده/مسدود/نیازمند مالک و مأموریت بعدی بده.
