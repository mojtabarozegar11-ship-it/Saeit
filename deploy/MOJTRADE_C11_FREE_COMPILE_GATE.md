# MojTrade C11 — دروازه کامپایل رایگان و بدون معامله

## هدف

محیط فعلی نه `.NET SDK` دارد و نه `ctrader-cli`. به‌جای اعلام
ساختِ تأییدنشده، گردش کار `.github/workflows/mojtrade-cbot-build.yml`
روی **GitHub Actions استاندارد و مخزن عمومی** فقط کامپایل دو cBot را انجام می‌دهد.
استفاده از رانر استاندارد GitHub برای مخزن عمومی بر اساس مستندات GitHub
رایگان است؛ این قاعده به رانرهای بزرگ یا مخزن خصوصی تعمیم داده نمی‌شود.

## مرزهای ایمنی

- گردش کار تنها اجازه `contents: read` دارد؛ اعتبارنامه checkout ذخیره
  نمی‌شود، هیچ secret، API کارگزار یا داده مالی نیاز ندارد.
- رویدادهای `push` برای شاخه‌های `fix/mojtrade-c*` و تغییر مسیرهای مرتبط
  فعال است؛ `pull_request` و `workflow_dispatch` نیز تعریف شده‌اند.
- رانر از SDK دات‌نت ۸ استفاده می‌کند؛ چارچوب هدف هر پروژه `net6.0` است،
  چون اجرای واقعی شماره 42458681008 نشان داد بسته پین‌شدهٔ
  `cTrader.Automate 1.0.21` چارچوب `net8.0` را با خطای CT0004 رد می‌کند.
  این انتخاب صرفاً دروازه **ساخت** است و سازگاری اجرای cTrader CLI را
  هنوز تضمین نمی‌کند.
- فایل محدود به همین پروژه در `trading/build/global.json` نسخهٔ SDK را
  روی شاخه ۸ قفل می‌کند. لاگ اجرای نخست نشان داد بدون این فایل، با وجود
  نصب SDK ۸، فرمان `dotnet --version` نسخهٔ ۱۰ را انتخاب می‌کرد.
- اسکریپت پس از ساخت هر پروژه **دقیقاً یک فایل `.algo` تازه** را اجباری
  می‌کند؛ چون بستهٔ cTrader در CI نام `build.algo` داد، از آن یک نسخه
  با نام اختصاصی همان ربات در خروجی ساخت می‌سازد و هش SHA-256 را ثبت
  می‌کند. **نام فایل به معنی تأیید نام داخلی یا متادیتای cTrader نیست.**
- نه انتقال به VPS، نه نصب سرویس، نه انتشار فایل در بازار، نه ارسال سیگنال
  و نه اجرای سفارش در این workflow وجود دارد.
- زمان هر اجرای کامپایل به ۱۲ دقیقه محدود و اجرای قدیمی هم‌زمان لغو می‌شود.
- اجرای واقعی 42458932532 پس از اصلاح `net6.0` برای هر دو ربات موفق بود.
  هشدار CS0618 در Omega X به استفاده از امضای قدیمی `ModifyPosition`
  مربوط بود؛ در اصلاح بعدی به امضای `ProtectionType.Absolute` تغییر کرد.
- اجرای 42459111272 بدون خطای C# کامپایل کرد، اما بررسی نام `.algo`
  شکست خورد؛ این اشکال بسته‌بندی با تشخیص فایل اصلی و ساخت نام صادراتی
  جداگانه اصلاح شد و نیازمند اجرای موفق بعدی است.

## محدودیت خروجی

«موفقیت کامپایل» فقط وقتی قابل اعلام است که **اجرای واقعی GitHub Actions**
برای آخرین commit این شاخه موفق شود و برای هر دو ربات فایل `.algo` تازه
بسازد. موفقیت تست‌های Python یا وجود workflow به‌تنهایی دلیل کامپایل نیست.

حتی پس از موفقیت CI، بررسی متادیتای فایل `.algo`، اتصال TLS، حساب DEMO،
سنجش بازه UTC و تأیید VPS لازم است؛ اجرای مداوم باید مستقل از GitHub Actions
روی VPSِ مجاز باشد. تا آن زمان هیچ معامله‌ای مجاز نیست.
