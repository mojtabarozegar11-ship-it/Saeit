# میز مدیریت و حسابداری — مرزهای خودکارسازی

این بخش مستقل از GitHub Actions در زمان اجراست. مسیر خصوصی `/staff/command-center/integrated/` از داده‌های موجود Django گزارش می‌گیرد؛ `GET` هیچ صف یا سندی را تغییر نمی‌دهد. مسیر حسابداری `/staff/command-center/accounting/` فقط اسناد `posted` را در مانده‌ها نمایش می‌دهد.

پایش دوره‌ای اعلان‌ها از `api/integrated-ledger/?view=approvals` استفاده می‌کند تا فقط صف تأیید همان کاربر را، بدون تکرار کوئری‌های سنگین چرخه و حسابداری، بخواند؛ پاسخ‌ها دارای `no-store` هستند.

## پایش خودکار بدون نیروی انسانی

فرمان استاندارد زیر روی سروری که نسخهٔ فعال Django را اجرا می‌کند، خروجی JSON قابل‌ماشین‌خواندن تولید می‌کند:

```bash
python manage.py audit_management_cycles
```

در زمان‌بند مستقل از GitHub (cron کنترل‌پنل/سرور) می‌توان این فرمان را با محیط پایتون فعال همان سایت به‌صورت ساعتی اجرا کرد. محیط اجرا، مسیر پروژه و مسیر **خصوصی** ذخیرهٔ لاگ باید روی همان سرور بررسی شوند. تا زمان ثبت رسید اجرای cron نمی‌توان ادعا کرد زمان‌بندی فعال شده است. خروجی ممکن است شناسهٔ پروژه و آمار مالی داشته باشد؛ نباید در `public_html` یا لاگ عمومی منتشر شود. برای لاگ‌ها چرخش و محدودیت حجم ضروری است.

- تعداد چرخه‌های دارای گزارش برای هر پروژه جداست؛ از ۵۰ چرخه، پوشش خالی با `next_unreported` مشخص می‌شود.
- `recorded_actions` تعداد گزارش‌های ثبت‌شده است، نه تعداد اقدام‌های تأییدشده.
- `no_result_reference`، `done_without_evidence` و `overdue_open_work` فقدان خروجی واقعی یا دیرکرد را آشکار می‌کنند.
- `finance_integrity` تراز مجموع بدهکار و بستانکار اسناد قطعی را بررسی می‌کند، اما **اثبات وصول وجه یا صحت تراکنش بانکی نیست**.
- برای رفع مانع ابتدا منبع تأیید و سپس مدرک رفع کامل ثبت می‌شود؛ دوباره‌بستن مانع مجاز نیست.
- `--strict` برای عدم‌توازن سند قطعی یا کار معوق کد خروجی غیرصفر می‌دهد؛ ارسال ایمیل، پرداخت، پاکسازی، انتشار و تأیید مالک انجام نمی‌شود.

## محدودهٔ کنترل خودکار

فقط متن‌های دقیق `monitor:systems` و `monitor:work` (یا دو عبارت فارسیِ ثابت متناظر) پایش خواندنی را اجرا می‌کنند؛ متن آزاد به‌عنوان دستور اجرایی تفسیر نمی‌شود. هیچ فرمان ثبت‌شده‌ای به‌خاطر بازشدن داشبورد به حالت «اجراشده» تغییر نمی‌کند.

درخواست‌های حساس از چرخهٔ canonical `ApprovalService` می‌گذرند. صاحب تعیین‌شده باید با حساب خودش تأیید کند. ثبت تصمیم عمومی `ApprovalDecision` فقط سابقه است و هیچ کار خارجی اجرا نمی‌کند. برای اسناد قطعیِ مالی، ویرایش و حذف در پنل Django Admin مسدود است؛ اصلاح مالی باید با سند جدید و مرجع قابل حسابرسی انجام شود.

## مواردی که هنوز خودکار نیستند

۱. اتصال معتبر و دارای رسید به هر یک از چرخه‌های مستقل ChatGPT/کارخانه/فروشگاه؛ شمارنده‌های صفحه سند انجام آن کارها نیستند.
۲. عامل اجرایی معتبر برای تغییر واقعی سایت‌ها، صدور فاکتور، آشتی بانکی، وصول وجه و تحویل محصول.
۳. فعال‌سازی cron در cPanel و اثبات اجرای آن در سرور تولید.
۴. اعتبارسنجی مستقل شواهد هر نتیجه و سازوکار تشخیص تکرار معنایی (فراتر از کلید یکسان اقدام در یک پروژه/چرخه).

تا این موارد با رسید واقعی اثبات نشوند، سامانه را باید «پایش و کنترل داخلی خودکارِ آمادهٔ نصب» دانست، نه مدیریت تجاری کاملاً خودگردان.
